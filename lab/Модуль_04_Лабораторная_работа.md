```text
Модуль 04
Тема: Модуль 04 DTO и AutoMapper Репозиторий с использование EF Core
Цель работы: научиться создавать слой доступа к данным в ASP.NET Core Web API с использованием Entity Framework Core, шаблона Repository, DTO и AutoMapper.
В презентации EF Core рассматривается как ORM для работы с БД через .NET-объекты, а DbContext и DbSet - как основные компоненты взаимодействия с данными. Отдельно рассматривается Repository как абстракция над доступом к данным и AutoMapper для преобразования Entity ↔ DTO
Задание
Создайте ASP.NET Core Web API для управления товарами (Product).
Модель товара:
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
    public string Category { get; set; }
}
В ходе лабораторной работы необходимо:
Подключить Entity Framework Core и настроить подключение к базе данных через appsettings.json.
Создать собственный класс:
AppDbContext : DbContext
и добавить:
public DbSet<Product> Products { get; set; }
В презентации DbContext отвечает за взаимодействие с БД и отслеживание изменений, а DbSet используется для работы с конкретными сущностями.
Используя подход Code First, создать базу данных с помощью миграции. В презентации Code First описывается как подход, при котором сначала создаются классы предметной области и контекст, после чего EF Core формирует или обновляет БД посредством миграций.
Создать интерфейс репозитория:
public interface IProductRepository
{
    Task<IEnumerable<Product>> GetAllAsync();
    Task<Product?> GetAsync(int id);
    Task CreateAsync(Product product);
    Task UpdateAsync(Product product);
    Task DeleteAsync(int id);
}
Реализовать его в классе:
ProductRepository
Все обращения к AppDbContext из контроллера должны выполняться через Repository, а не напрямую.
Создать DTO:
public class ProductDto
{
    public int Id { get; set; }
    public string Name { get; set; }
    public decimal Price { get; set; }
}
Обратите внимание: Category специально отсутствует в DTO – можно увидеть разницу между Entity и объектом, который API возвращает клиенту.
Подключить AutoMapper и создать профиль:
public class AutoMapperProfile : Profile
{
    public AutoMapperProfile()
    {
        CreateMap<Product, ProductDto>().ReverseMap();
    }
}
Такой подход соответствует рассмотренной в презентации настройке CreateMap<...>().ReverseMap().
Создать ProductsController и реализовать CRUD API:
GET     /api/products
GET     /api/products/{id}
POST    /api/products
PUT     /api/products/{id}
DELETE  /api/products/{id}
Для ответов API использовать единый ReturnResult. Согласно презентации, единый контракт делает ответы API предсказуемыми, но при этом не должен заменять HTTP status codes.
{
  "isSuccess": true,
  "result": {
    "id": 1,
    "name": "Ноутбук",
    "price": 350000
  },
  "errorMessage": []
}
Результат лабораторной: готовый Web API, в котором реализована цепочка:
Database → EF Core → Repository → AutoMapper → DTO → Controller → API Response
```

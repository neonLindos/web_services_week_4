```text
Модуль 04
Тема: Модуль 04 DTO и AutoMapper Репозиторий с использование EF Core
Цель работы: совместно с преподавателем разработать часть ASP.NET Core Web API, применив Entity Framework Core, Repository, DTO и AutoMapper. В презентации эти компоненты рассматриваются как последовательные элементы работы с данными: EF Core обеспечивает ORM-доступ к БД, Repository отделяет логику доступа к данным, а AutoMapper используется для преобразования Entity ↔ DTO.
Задание
Разработайте Web API для управления командами (Team). Первую часть работы выполняйте пошагово вместе с преподавателем, вторую — самостоятельно.
Часть 1. Вместе с преподавателем
Создайте модель Team, содержащую поля:Id, Name, City, Description.
Подключите Entity Framework Core к проекту.
Создайте класс AppDbContext, унаследованный от DbContext, и добавьте:
public DbSet<Team> Teams { get; set; }
Добавьте строку подключения к базе данных в appsettings.json и зарегистрируйте AppDbContext через Dependency Injection. Работа DbContext, DbSet и подключение через конфигурацию рассматриваются в презентации.
Создайте интерфейс ITeamRepository с методами:
Task<IEnumerable<Team>> GetAllAsync();
Task<Team?> GetAsync(int id);
Task CreateAsync(Team team);
Task UpdateAsync(Team team);
Task DeleteAsync(int id);
Создайте класс TeamRepository и реализуйте в нём методы работы с БД через EF Core.
Зарегистрируйте Repository в Dependency Injection.
Создайте TeamDto. DTO должен содержать только:
Id
Name
City
Поле Description клиенту возвращать не нужно.
Подключите AutoMapper и настройте преобразование:
CreateMap<Team, TeamDto>().ReverseMap();
Такой вариант настройки AutoMapper непосредственно используется в презентации.
Создайте TeamController и совместно с преподавателем реализуйте:
GET /api/team
GET /api/team/{id}
POST /api/team
Для ответов API используйте единый класс ReturnResult, рассмотренный в презентации.
Часть 2. Самостоятельное задание студентам
Продолжите разработку созданного Web API.
Реализуйте самостоятельно:
PUT    /api/team/{id}
DELETE /api/team/{id}
При выполнении необходимо соблюдать архитектуру:
Client
  ↓
Controller
  ↓
DTO ↔ AutoMapper ↔ Entity
                     ↓
                 Repository
                     ↓
                  EF Core
                     ↓
                 Database
Дополнительно добавьте метод поиска команд по городу:
GET /api/team/city/{city}
Метод должен возвращать только команды указанного города.
Требования к результату
К концу практической работы приложение должно позволять добавлять, получать, изменять, удалять и искать команды. Все операции с БД должны выполняться через
Repository, наружу должны возвращаться DTO, преобразование Entity ↔ DTO должно выполняться через AutoMapper, а endpoints должны использовать единый формат ответа ReturnResult.
На защиту: продемонстрируйте работу API через Swagger и будьте готовы объяснить цепочку:
Controller → Repository → EF Core → Database
Entity → AutoMapper → DTO → клиент
```
